ĐẶC TẢ HỆ THỐNG E-COMMERCE

1. GIỚI THIỆU ĐỀ TÀI

  • Mục tiêu hệ thống: Xây dựng một nền tảng thương mại điện tử chuyên cung cấp các thiết bị điện tử (điện thoại, laptop, phụ kiện) với trải nghiệm mua sắm mượt mà, tốc độ phản hồi cao và có khả năng chịu tải tốt trong các sự kiện siêu sale.
  • Đối tượng sử dụng:
    • Người tiêu dùng cá nhân (B2C) có nhu cầu mua sắm thiết bị công nghệ.
    • Đội ngũ vận hành (Admin/Staff) quản lý kho hàng, đơn hàng và chiến dịch marketing.
  • Bài toán thực tế giải quyết: Giải quyết tình trạng nghẽn cổ chai (bottleneck) khi có lượng lớn truy cập đồng thời, ngăn chặn việc bán vượt quá số lượng tồn kho (overselling) và tối ưu hóa quy trình quản lý đơn hàng.
  • Phạm vi hệ thống: Quản lý toàn bộ vòng đời của sản phẩm từ khi nhập kho đến khi giao tới tay khách hàng, tập trung vào nghiệp vụ giỏ hàng, thanh toán trực tuyến và chiến dịch Flash Sale.
  • Giá trị mang lại: Một hệ thống tiệm cận production, có thể dễ dàng mở rộng, tích hợp các cổng thanh toán nội địa (như VNPay, MoMo) và là minh chứng rõ ràng cho tư duy thiết kế hệ thống lớn.

2. PHÂN TÍCH NGHIỆP VỤ (BUSINESS LOGIC)

N nghiệp vụ Khách hàng (Customer)

  • Xác thực: Đăng ký, Đăng nhập (Local & OAuth2 Google), Quên mật khẩu (gửi OTP qua Email).
  • Mua sắm:
    • Tìm kiếm realtime (debounce), Lọc sản phẩm (theo giá, thương hiệu, đánh giá, thông số kỹ thuật).
    • Thêm vào giỏ hàng (lưu trữ đồng bộ trên DB thay vì chỉ ở LocalStorage để cross-device).
    • Thanh toán (Checkout): Tính phí ship, áp dụng Voucher, chọn phương thức thanh toán.
  • Hậu mãi & Tương tác:
    • Theo dõi trạng thái đơn hàng (Pending → Processing → Shipped → Delivered).
    • Đánh giá sản phẩm (chỉ cho phép khi đơn hàng đã hoàn thành).
    • Wishlist (Lưu sản phẩm yêu thích).
    • Nhận thông báo (Realtime qua Socket.io).

N nghiệp vụ Quản trị (Admin)

  • Quản lý Catalog: Thêm/sửa/xóa sản phẩm, danh mục, thương hiệu. Quản lý các biến thể sản phẩm (Màu sắc, Dung lượng RAM/ROM).
  • Quản lý Đơn hàng & Tồn kho: Cập nhật trạng thái đơn hàng, theo dõi lịch sử xuất/nhập kho.
  • Marketing: Tạo mã giảm giá (Voucher) với các rule phức tạp, thiết lập lịch chạy Flash Sale.
  • Thống kê (Dashboard): Biểu đồ doanh thu theo tháng/tuần, Top sản phẩm bán chạy, Tỷ lệ chuyển đổi (Conversion Rate).

3. PHÂN TÍCH ROLE & PHÂN QUYỀN

Thiết kế RBAC (Role-Based Access Control) với 4 cấp độ:

  • Guest (Khách vãng lai): Chỉ được xem sản phẩm, đọc đánh giá, thêm vào giỏ hàng (lưu LocalStorage). Bị chặn ở bước Checkout.
  • Customer (Khách hàng): Có đầy đủ quyền mua sắm, quản lý profile, lịch sử đơn hàng, sử dụng voucher.
  • Staff (Nhân viên): Truy cập CMS Admin. Được quyền xử lý đơn hàng, cập nhật trạng thái kho, phản hồi đánh giá. Không được xem doanh thu tổng hay cấp quyền tài khoản.
  • Admin (Quản trị viên): Toàn quyền hệ thống. Quản lý phân quyền Staff, xem Dashboard doanh thu, can thiệp vào mọi data.

4. DATABASE DESIGN (MongoDB)

Tư duy thiết kế: Tối ưu cho thao tác Đọc (Read) vì E-commerce có tỷ lệ Read/Write thường là 10:1.

Các Collection chính & Cấu trúc

  • users: _id, name, email, password (hashed), role, status (active/banned).
  • products: _id, name, slug, description, price, discount_price, stock, category_id (Ref), brand_id (Ref), variants (Array of objects: màu sắc, dung lượng), images (Array), ratings_average.
  • categories / brands: _id, name, slug, image.
  • carts: _id, user_id (Ref), items (Array: product_id, variant, quantity). Lý do: Tách riêng thay vì nhúng vào user để tránh document quá lớn khi khách hàng thêm nhiều đồ.
  • orders: _id, user_id, total_amount, shipping_fee, discount_amount, final_amount, payment_method, status (Enum), shipping_address (Object).
  • order_items: _id, order_id (Ref), product_id (Ref), price_at_buy, quantity. Lý do: Tách riêng giúp dễ dàng query thống kê sản phẩm bán chạy.
  • flash_sales: _id, name, start_time, end_time, products (Array: product_id, promo_price, sold_quantity, max_quantity), status.
  • vouchers: _id, code, discount_type (percent/fixed), value, min_order_value, max_discount, start_date, end_date, usage_limit, used_count.

Database Best Practices

  • Soft Delete: Thêm trường is_deleted: boolean và deleted_at vào bảng products/users. Tuyệt đối không xóa vật lý để giữ toàn vẹn dữ liệu cho đơn hàng cũ.
  • Indexing:
    • products: Index slug (Unique) cho SEO URL, Text Index cho name để tối ưu thanh tìm kiếm.
    • orders: Index user_id và created_at để truy xuất lịch sử nhanh.
  • Timestamps: Tích hợp sẵn createdAt và updatedAt của Mongoose cho mọi collection.

5. THIẾT KẾ KIẾN TRÚC BACKEND

Sử dụng kiến trúc Layered Architecture chuẩn mực để dễ maintain và test:

  • routes/: Chứa định tuyến API, gắn các middleware authentication và validation.
  • controllers/: Tiếp nhận request, gọi service xử lý, trả về response. Tuyệt đối không chứa logic nghiệp vụ phức tạp ở đây.
  • services/: Nơi chứa toàn bộ Business Logic (tính toán giá, xử lý giỏ hàng, áp mã giảm giá). Trái tim của backend.
  • models/: Schema Mongoose định nghĩa cấu trúc DB.
  • middlewares/:
    • auth.middleware: Xác thực JWT, phân quyền Role.
    • error.middleware: Global Error Handler bắt mọi exception.
  • validations/: Joi hoặc Zod để validate input req.body trước khi vào controller.

Flow Request Lifecycle:

Client Request → Router → Auth Middleware → Validation Middleware → Controller → Service → Database → Service → Controller → Client Response.

Chuẩn Response Format (JSend):

{
  "status": "success",
  "message": "Lấy danh sách sản phẩm thành công",
  "data": { ... },
  "metadata": { "page": 1, "total": 50 }
}

6. API DESIGN (RESTful)

Một số API cốt lõi (sử dụng danh từ số nhiều, method chuẩn):

HTTP Method Endpoint Authorization Mục đích
POST /api/v1/auth/login Public Xác thực người dùng, trả về Access/Refresh Token

GET /api/v1/products/:slug Public Lấy chi tiết sản phẩm

7. FRONTEND STRUCTURE (ReactJS + TailwindCSS)

Kỹ thuật Frontend:

  • Data Fetching: Dùng React Query (TanStack Query) kết hợp Axios để tự động caching, quản lý loading/error state.
  • Performance: Sử dụng React.lazy() và Suspense để code-splitting các trang lớn.
  • Infinite Scroll: Cho trang danh sách sản phẩm thay vì pagination truyền thống để tăng trải nghiệm.

8. THIẾT KẾ UI/UX

  • Trang chủ: Banner lớn (Carousel), Flash Sale section (có đồng hồ đếm ngược), Danh mục nổi bật, Gợi ý hôm nay (Recommendation).
  • Trang chi tiết SP: Ảnh slider bên trái. Bên phải gồm: Tên, Giá (cũ/mới), Biến thể (chọn màu/RAM cập nhật giá realtime), Nút "Thêm vào giỏ" & "Mua ngay". Dưới cùng là Thông số kỹ thuật & Đánh giá (có filter theo số sao).
  • Thanh toán: Checkout một trang (One-page checkout). Chia làm 2 cột: Cột trái nhập địa chỉ, cột phải tóm tắt giỏ hàng, ô nhập voucher và tổng tiền.
  • Admin Dashboard: Sidebar cố định bên trái. Không gian chính hiển thị biểu đồ Chart.js trực quan. Bảng dữ liệu có phân trang, tìm kiếm và export ra Excel.

9. FEATURE NÂNG CAO ĐỂ ĐỒ ÁN NỔI BẬT

  • Hệ thống Voucher thông minh: Áp dụng thuật toán để tự động tính toán Voucher nào có lợi nhất cho người dùng khi họ có nhiều mã.
  • Product Search Advanced: Tìm kiếm Full-text search kết hợp debounce 500ms để giảm tải server. Gợi ý từ khóa ngay khi gõ (Autocomplete).
  • Tích hợp thanh toán thật: Tích hợp sandbox của VNPay hoặc MoMo. Hội đồng rất thích những đồ án có flow dòng tiền thực tế.
  • Realtime Notifications: Khi đơn hàng đổi trạng thái từ "Đang xử lý" sang "Đang giao", bắn socket cập nhật ngay lập tức icon cái chuông trên Navbar của user.

10. THIẾT KẾ FLASH SALE CHUYÊN SÂU (FEATURE "ĂN ĐIỂM")

Bài toán: Có 10 cái iPhone giá 1 triệu. 1000 người click "Mua" cùng một giây. Nếu code không chuẩn, DB sẽ ghi nhận bán được 100 cái (Overselling).

Giải pháp với MongoDB (Atomic Operations & Optimistic Locking):

1. Thiết kế luồng (Sequence Flow):

  • User vào trang Flash Sale (Lấy data qua Cache nếu có, hoặc DB).
  • Click "Mua ngay" → Đẩy request vào backend.
  • Giữ chỗ (Reserve Stock): Backend sử dụng toán tử $inc của MongoDB kèm theo điều kiện lọc để trừ tồn kho nguyên tử (Atomic).

2. Code pattern chống Oversell:

// Update nguyên tử: Chỉ trừ stock nếu stock hiện tại lớn hơn số lượng muốn mua
const product = await Product.findOneAndUpdate(
  {
    _id: productId,
    stock: { $gte: quantityToBuy } // Điều kiện tiên quyết
  },
  {
    $inc: { stock: -quantityToBuy } // Trừ đi
  },
  { new: true }
);

if (!product) {
  throw new Error("Sản phẩm đã bán hết hoặc không đủ số lượng!");
}
// Tiến hành tạo Order

Lý do: Toán tử của MongoDB đảm bảo ở tầng database, hai request đến cùng một microsecond cũng sẽ được xử lý tuần tự. Mệnh đề $gte đảm bảo stock không bao giờ bị âm.

3. Xử lý Rollback (Hủy đơn trả lại kho):

Khi user "Giữ chỗ" thành công, hệ thống tạo một Job (có thể dùng node-cron hoặc TTL index của MongoDB) để đếm ngược 10 phút. Nếu user không thanh toán (Payment Pending), hệ thống tự động Hủy đơn và $inc cộng lại số lượng vào stock.

4. Realtime Countdown:

Frontend tính toán countdown dựa trên server_time trả về từ API (không dùng giờ local của máy tính user để tránh bị hack). Khi đếm ngược về 0, call API kiểm tra hoặc reload section.

11. BẢO MẬT HỆ THỐNG

  • Authentication:
    • Dùng Access Token (tuổi thọ ngắn: 15-30p) lưu ở bộ nhớ Frontend.
    • Refresh Token (tuổi thọ dài: 7-30 ngày) lưu ở httpOnly cookie để tránh mã độc XSS lấy cắp.
  • Rate Limit: Dùng express-rate-limit chặn spam API (vd: 100 requests/15 phút trên mỗi IP). Riêng API Đăng nhập/OTP chặn gắt hơn (5 req/phút) để chống Brute Force.
  • Security Headers: Dùng middleware helmet để che giấu thông tin Express, thiết lập các header chống Clickjacking.
  • Chống NoSQL Injection: Dùng express-mongo-sanitize để loại bỏ các ký tự $ trong request body, tránh hacker bypass logic đăng nhập.
  • Validate Dữ liệu: Tất cả API phải đi qua Joi/Zod, chặn nghiêm ngặt các field thừa (strip unknown).

12. KẾ HOẠCH THỰC HIỆN ĐỒ ÁN

Roadmap dự kiến cho 12 tuần (3 tháng):

  • Phase 1: Phân tích & Thiết kế (Tuần 1 - 2)
    • Chốt scope nghiệp vụ, vẽ Use Case, ERD Database.
    • Setup repository GitHub, cấu hình CI cơ bản.
    • Thiết kế UI trên Figma (hoặc clone UI Shopee/Tiki).
  • Phase 2: Core Backend & CMS (Tuần 3 - 6)
    • Xây dựng kiến trúc ExpressJS, kết nối MongoDB.
    • Làm API Auth, CRUD Sản phẩm, Danh mục, User.
    • Build trang Admin Frontend (Quản lý và Dashboard).
  • Phase 3: Customer Frontend & Core Features (Tuần 7 - 9)
    • Build trang chủ, trang chi tiết sản phẩm.
    • Xử lý logic Giỏ hàng, Checkout, luồng Thanh toán (Tích hợp VNPay).
  • Phase 4: Advanced Features & Hoàn thiện (Tuần 10 - 12)
    • Triển khai hệ thống Flash Sale & Inventory locking.
    • Kiểm thử chịu tải cơ bản, fix bug, responsive UI.
    • Deploy lên Cloud (Sử dụng GCP VM instance hoặc Render/Vercel).
    • Viết báo cáo luận văn, chuẩn bị slide và kịch bản demo bảo vệ.
